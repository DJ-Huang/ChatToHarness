# 网页写入延迟分段与修复验收（2026-10-20）

安全编辑现在在一次调用内完成写入、重新打开实际文件、完整 SHA-256 核验和有界文本读回。相同目标的实际 Edge 网页对照中，工具调用从两次减少到一次，浏览器收齐最终答案的时间从 **15.792 秒降到 9.448 秒（本组减少 40.2%）**，两次网页均实际显示最终内容。没有调整超时、模型、代理或安全设置。

这是单组实测，不能保证每次请求都有同样提升。首次本机收件仍用了 6.34 秒，本轮没有将其消除，也没有把不可见的上游时间归因于某一个组件。

## 先前 9.2 秒与 4.6 秒能确认什么

[最初写入记录](chat-web-recovery-20261020.md)中的 22.406 秒是发送到观察的上界。当时记录到首次本机收件前 9.163 秒，以及两次本地调用之间约 4.6 秒，但没有同次请求的完整浏览器分段。无法从旧日志倒推出其中每毫秒的模型、服务器和网络占比。

源码及日志确认，两轮调用复用同一个私有网关连接和健康服务。重复 `initialized` 是上游协议通知，没有重新启动进程或扫描工具目录。为避免继续猜测，新增脱敏计时记录本机帧接收/解析、初始化响应、请求派发和结果写出；通过原生 Edge DevTools 的 EventStream 读取同机浏览器接收时间，与本机日志关联。

浏览器接收到工具调用事件，不等于云端刚刚开始发起该调用；工具事件流与工具执行是两个传输路径。因此下面的跨路径差值是观测边界，不能直接叫作纯网络延迟。所有对照计算使用这台电脑上的发送/接收时间，未混用服务器 `create_time`，也未读取原始思维内容。

## 本轮修改

- `apply_project_edit` 在保存完成后重新打开目标文件，哈希覆盖完整文件。`verification` 返回实际哈希、匹配状态、字节数、时间和最多 4 KiB 的完整 UTF-8 前缀。`complete/truncated` 只描述预览完整性，不代表哈希只校验了部分内容。
- 工具说明及输出 schema 明确新建文件用 `expected_sha256="absent"`；已有文件仍须当前 SHA-256。`matched` 且预览完整时，从该次真实读回结果回答即可，无须为核对再次调用读取工具。
- 幂等重试只重新核验当前文件，不重复写入，历史结果不会伪装成当前内容。已写入但读回失败与写入/耐久结果未知分开报告，前者保留 `operation_executed:true / completed`；撤销及原耐久写入不变。
- 精简内置工具的长说明，去掉按 25–30 行分块写入等诱发额外调用的建议。保留工具名、输入结构、格式支持、权限及原有入口，不改第三方工具说明。
- 工具目录页上限从 32 调为 64，保留既有字节限制和版本游标。网页刷新实际取得 46 个业务工具且无下一页；这改善目录加载，不能拿来解释每次业务调用的等待。
- 新增本机协议阶段计时，仅保存固定方法、会话/请求本地序号和有界数值，不保存协议参数、原始 ID、凭证或响应正文。三语使用说明和执行记录文档同步更新。

同一 48 项模型元数据快照中，仅替换说明的静态对比为 73,793 → 56,523 字节（约少 23.4%），说明正文少约 58%。它不是实际网页传输体积，也不能证明首次等待已因此下降。新增校验 schema 等另有少量体积开销。

这与官方关于[减少顺序请求](https://developers.openai.com/api/docs/guides/latency-optimization)和[用明确工具参数与结果支持用户目标](https://developers.openai.com/plugins/plan/tools)的建议一致；没有引入新 HTTP 通道、通用后台轮询或通过省略项目指引降低调用数。

## 验证与边界

最小相关检查通过：安全编辑 9 项、服务接口 12 项、网关/传输 25 项，以及工具说明/目录 4 项。安全编辑在审阅发现执行语义问题后仅重跑该文件，9 项通过；未运行完整仓库套件。覆盖落盘后重新读取、UTF-8 边界、校验竞争、读回不可用、旧幂等记录、恢复不重放、指引先交付后写入、输出兼容和目录字节/游标限制。

本次消除了第二次远程核对调用，证据支持这组写入体验改善。首次请求前的时间仍包括网页到服务器、模型/编排、远端工具转发和通道传输；我们只能观察这些边界，无法给出 OpenAI 内部队列和模型计算各自的精确占比。新基线首次收件 5.44 秒，修改后 6.34 秒，故不宣称首调等待已改善。没有通过降低模型强度或改代理掩盖这一点。未修改此前用户暂存内容，未发布、推送、合并或重新提交原 Git 项目。

证据位于 `.cache/chat-web-experience-20261020/recovery/`：`write-roundtrip-runs.json`、前后两个 `*-stream-timeline.json`、`write-roundtrip-backend-evidence.json`、`write-roundtrip-after-network-timing.txt`、`write-roundtrip-before-visible.png`、`write-roundtrip-after-visible.png`。其中时间线只保留阶段名称与本机接收时间，不保存原始事件流正文或令牌。
