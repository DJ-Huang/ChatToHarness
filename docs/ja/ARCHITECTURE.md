# ChatToHarness アーキテクチャ

[English](../en/ARCHITECTURE.md) | [简体中文](../zh-CN/ARCHITECTURE.md) | [日本語](../ja/ARCHITECTURE.md)

処理経路は、対応クライアント → OpenAI Secure MCP Tunnel → ローカル Tunnel runtime → プロジェクト規約プロキシ → Desktop Commander です。外部クライアントの接続先は Tunnel のみです。内部の stdio やループバックのヘルスチェックは、追加の公開 MCP 接続先ではありません。

## デスクトップ層

Electron のメインプロセスが、設定、システム暗号化された認証情報、単一起動、ウィンドウ、バックグラウンドアイコン、接続キューを管理します。HTML/CSS/JavaScript は 4 つの独立した画面を提供します。制限付き preload から設定、ディレクトリ選択、状態購読、接続操作を公開します。レンダラーの Node アクセスは無効で、サンドボックス、コンテキスト分離、画面遷移制限、外部リンクの許可リストを使用します。

ウィンドウを閉じると非表示になります。停止と終了は `actionEpoch` を更新し、待機中の自動接続や設定保存後の接続処理を取り消します。自動キー読み取りは画面の読み込み後に開始し、システム許可ダイアログで初期表示が止まらないようにします。公開状態にはキーの保存有無だけを含め、平文や暗号文は返しません。

Mac は LocalHarness の内部名、アプリ識別子、データ保存先を維持し、表示名だけを ChatToHarness にします。Windows は専用のシステムデータディレクトリを使います。システム暗号化を利用できない場合、平文保存には切り替えません。読み取り失敗時も元の設定を保持します。Windows のユーザー単位の暗号化は、同じユーザーで動く別のプログラムからの隔離を意味しません。

## プラットフォームとプロセス管理

プラットフォームアダプターは、コンポーネントの位置、既定 Shell、ユーザー環境、Tunnel のコマンド引数、プロセス監視を担当します。Mac は所有するプロセスとプロセスグループを回収します。Windows はコンパイル済みの Job Object ヘルパーでプロセスツリーを管理し、Job を閉じると子孫プロセスも終了します。Tunnel のキーは環境変数だけで渡し、ランチャーは Desktop Commander の起動前にその変数を削除します。

同梱する Node などのコンポーネントは、固定バージョンとチェックサムで準備します。ツールの設定とログは専用データディレクトリに置き、実際の HOME／USERPROFILE を保持し、テレメトリーを無効にします。ビルド時の Desktop Commander 設定保存先の修正は既知のソースとの完全一致を要求し、一致しない場合はビルドを停止します。

## プロジェクト規約と検索

`get_project_context(project_path, target_paths?, rule_paths?)` は従来の本文・索引・トークンに `blocks_writes` 付き `diagnostics` を追加します。規約の適用範囲とアプリの許可フォルダーを別々に検査し、共有規約は許可範囲内ならプロジェクトをまたいで読めます。対象や書き込み権限は広げません。AGENTS 不在は正常、参照失敗は診断のみで、適用 AGENTS の取得不能だけを書き込みの阻止条件とします。

読み取りは規約を自動添付し、有効なトークンで本文を再利用します。初回の書き込みに規約が必要なら、実行せず本文と再試行トークンを返します。キャッシュは有界で、ファイルとディレクトリのメタデータを使い、変更時だけ本文を読みハッシュを更新し、同時取得を統合します。AGENTS は既知の名前を確認し、索引は上限付きストリーム列挙を使います。索引と渡した規約のバージョンは独立しています。

`search_project` は Shell を使わず同梱 ripgrep に引数配列を渡します。既定は文字列検索、2 秒、1 ページ 100 件、前後各 2 行です。最大 1,000 件、保存 2 MiB、結果の 1 ページ 64 KiB、同時 4 件、最大 10 秒に制限します。プロジェクトとクエリーに対応する保存結果は未使用 5 分で失効し、完了・該当なし・時間やサイズ上限・部分失敗を区別します。従来の検索ツールも残します。

待機リクエストは有界で既定 60 秒、明示した待機で最大 180 秒です。キャンセルは規約と検索に伝播し、切断時に待機表・キャッシュ・検索プロセスを回収します。転送前は `not_started`、転送後のタイムアウトは `unknown` とし、自動再実行しません。遅延応答は破棄します。継続と停止は発生元のハンドルに対応し、既知の停止に規約の再取得は不要です。ツールの schema・出力 schema・動作注記を合わせ、使用不能な Web 部品の指定を取り除きます。

## アプリの更新

独立した `Updater` が固定 GitHub リポジトリの公開安定版を確認し、数値バージョン、プラットフォーム、パッケージ URL、サイズ、SHA-256（`SHA256SUMS.txt` も対応）を検証します。メインプロセスの Electron `net.fetch` でシステムプロキシを使用し、レンダラーのネットワークと Node は無効のままです。既存の IPC 発信元検査を使い、外部 URL は検証済みメタデータからだけ取得します。

起動 10 秒後と以後 24 時間ごとに確認し、独立した設定で無効化できます。同時確認を統合し、認証情報や接続キューには触れません。クリック後に取得を開始し、ストリームとインストール前の両方で検証します。管理下の処理を停止してからインストーラーを開き終了します。失敗は再試行でき、終了で転送を中止します。7 日を過ぎた専用キャッシュは後続の確認時に回収します。テストモードは自動通信しません。

## ビルドと配布

GitHub Actions が Windows x64 と Mac arm64 のネイティブ環境でビルドし、同梱リソース、独立した設定での画面動作、インストールを検証します。両 OS の検証とアップロード確認が成功した場合のみ、更新情報と SHA-256 付きの安定版を自動公開し、サイト配信を直接呼び出します。公開済み Release は上書きしません。Pages は独立してビルドし、公開済み安定版だけをダウンロード対象にします。ソースとサイトにユーザー設定や認証情報を含めません。

[検証範囲](VERIFICATION.md)、[リリース管理](RELEASING.md)、[ドキュメント一覧](README.md)を参照してください。

## 多言語対応

`app/locales.js` と `app/i18n.js` を画面とネイティブメニューで共有し、静的文言、アクセシビリティラベル、実行状態、既知のエラーを翻訳します。初回はシステム言語を使い、ユーザーの選択は暗号化設定とは別の `preferences.json` に保存します。言語 IPC は接続キューや `actionEpoch` を変更せずにメニューと状態を更新します。パス、認証情報、ツールの出力は翻訳しません。

サイトはルート（中国語）、`/en/`、`/ja/` に完全な静的ページを生成し、メタ情報、文書リンク、ダウンロード状態、アプリ画像を各言語に合わせます。canonical と代替言語リンクを設定します。ブラウザーに選択を記憶し、英語・日本語 URL の直接指定を優先します。
