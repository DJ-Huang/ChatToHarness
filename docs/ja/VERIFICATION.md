# ChatToHarness 0.3.0 検証記録

[English](../en/VERIFICATION.md) | [简体中文](../zh-CN/VERIFICATION.md) | [日本語](../ja/VERIFICATION.md)

この記録では、自動チェック、各 OS での動作、実際のクライアント呼び出しを区別します。未完了の項目は未検証のままとし、コードが存在するだけで成功とは扱いません。

## 記録済みの結果

- ローカル Mac の単体チェックは 68 件中 66 件が成功し、Windows ネイティブの Job Object 2 件を Mac ではスキップしました。この 2 件は、その後 Windows CI で成功しています。
- ローカル Mac アプリと約 225 MB の DMG を生成し、署名の整合性確認が成功しました。独立した設定によるパッケージ済み画面の検証では、4 ページの移動、実際の 26 ツール、ディレクトリ選択、認証情報の暗号化保存・置換・消去、再起動後の再接続、重複起動、非表示と復元、3 世代の管理プロセスの回収、権限エラーからの復旧が成功しました。DMG の検査、マウント、中国語と空白を含むパスへのコピー、起動、ユーザーデータを保持したアプリ削除も成功しました。最終パッケージの完全な独立設定での画面検証も再度成功しています。
- GitHub の Windows／Mac ネイティブ CI は両方とも成功しました。Windows は 68 件中 67 件が成功し、POSIX 専用の 1 件をスキップしました。Job Object のネイティブ検証 2 件も成功しました。両 OS で、実際のツールエンジン、Tunnel 用のローカル模擬制御サービス、パッケージ、独立した設定での画面動作を検証しています。[CI 記録](https://github.com/DJ-Huang/ChatToHarness/actions/runs/39001994066)。
- Pages のオフラインビルド、リポジトリのサブパス、未公開ダウンロードの表示を確認しました。公開ページは HTTP 200 を返し、リソースが読み込まれ、デスクトップとモバイルで横方向のはみ出しはありませんでした。[デプロイ記録](https://github.com/DJ-Huang/ChatToHarness/actions/runs/39001761795)。
- 両 OS のインストーラー草稿を自動生成し、アップロード先のサイズと SHA-256 を照合しました。[配布ワークフロー](https://github.com/DJ-Huang/ChatToHarness/actions/runs/39002181642)はすべて成功しました。Mac DMG のマウント・コピー・起動と、Windows NSIS のインストール・起動・設定を保持したアンインストールを含みます。この記録時点では Release は草稿で、正式公開していません。
- 既存 Mac 設定と実際の Tunnel：新しいネイティブ画面は「通道就绪」で、26 ツールを利用可能と表示しました。更新前後で設定ファイルの SHA-256 が一致し、保存キー、ディレクトリ、各スイッチが保持されていることを確認しました。
- 現在の Codex セッションから既存の Tunnel プラグインへの実際の呼び出しが成功しました。プロジェクトコンテキストの自動取得、README の読み取り、読み取り専用の Git／HOME 確認、Shell 環境に Runtime キーがないこと、専用検証ディレクトリでのマーカー書き込みと読み戻しを確認しました。ChatGPT Web の読み取り専用検証では「返信を読み込めません」に相当する表示になり、プラグインなしで「OK とだけ返す」ように求めた新規チャットでも同じ問題が発生しました。このため Web の返信表示は外部の問題で検証が妨げられており、成功とは扱いません。Responses API／AgentKit は本バージョンでは公式資料への案内を提供し、実際の呼び出し成功は主張しません。

実際のローカル MCP のスモークテストでは、コンテキスト取得前の書き込み拒否、ルートと下位の AGENTS、必要な規約、規約更新による失効、プロジェクト間の移動、並行コンテキスト、ファイル読み書き、実際の HOME の保持、Shell からの Runtime キー除去が成功しました。実際の Tunnel runtime はローカルの模擬制御サービスに対して現在のコマンド引数を受け付け、ヘルスチェックを提供しました。これだけで外部トンネルの成功とは扱いません。

## 互換性の基準

0.2.0 では元の Mac で、プロジェクト規約の自動受け渡し、ルートと下位の AGENTS、必要に応じた rules、プロジェクト間コンテキスト、実際のツール読み書き、メニューバー動作を検証済みでした。その結果を自動的に 0.3.0 の成功と見なすことはしません。個人設定は公開リポジトリに含めません。

## 検証範囲

CI は一時設定、合成認証情報、模擬制御サービスを使用し、個人の Tunnel は使いません。ホストされた Windows 環境のインストール・自動検証は、利用者の端末での手動確認を代替しません。トンネルの準備完了はクライアント設定の完了を意味しません。通信復旧時に長時間のツール操作を自動再実行することもありません。

## 多言語・画像の確認（2026-10-17）

Mac の独立設定で、4画面の3言語表示、ネイティブメニュー、再起動後の言語記憶、未保存の入力保持を確認しました。切り替え前後で暗号化設定と管理対象プロセス ID は変わりません。アプリ画像は実際の画面と模擬トンネルで撮影し、実クライアントの呼び出し結果ではありません。サイト確認は3言語の静的パス、公開済み／未公開のダウンロード表示、対応する画像と文書リンクを対象とします。ChatGPT の3言語画像はタスク入力例であり、ツール呼び出し成功を示しません。

更新後のローカルチェックは71件中69件に成功し、Windows 専用の2件は Mac でスキップしました。

署名済み Mac アプリでも、3言語を含む独立したパッケージ画面チェックがすべて成功しました。

[両 OS のネイティブ CI](https://github.com/DJ-Huang/ChatToHarness/actions/runs/39004923858) と[3言語サイトの配信](https://github.com/DJ-Huang/ChatToHarness/actions/runs/39004923882)が成功しました。元の Mac に導入したアプリで3言語を切り替えても、実トンネルは準備完了のまま26ツールを利用でき、暗号化設定の指紋も変わりません。今回の言語確認では、以前の実クライアント読み書き検証は繰り返していません。
