# 成果物を確認して取得する

[English](../en/artifacts.md) | [简体中文](../zh-CN/artifacts.md) | [日本語](../ja/artifacts.md)

> ChatToHarness 0.6.0 対象。

## 目的

タスクが実際に生成したファイルを見つけ、内容を確認します。

## 始める前に

プロジェクトと出力先を把握します。ファイルツールで読めるのは許可範囲内の成果物です。

## 操作手順

1. タスク開始時に保存先を指定します。
2. 終了後、実在するファイルのパス・サイズ・種類を求めます。
3. テキストは必要に応じて分割し、対応する小さな画像はプレビューします。大きなファイルは分割して返る場合があります。
4. クライアントに実際の添付やリンクがあれば利用します。なければ本機のファイル管理画面で開きます。
5. 重要な内容とサイズを確認し、最終版を保存します。

### コピーして使える例文

例のパスは許可済みのプロジェクトの絶対パスに置き換えます。Windows では自分のドライブのパスを使ってください。

```text
/Users/demo/ExampleProject/output に実在するファイルのパス・サイズ・種類を一覧にし、対応する画像を表示してください。存在しないファイルを生成済みと報告しないでください。
```

操作の順序を示す図です。クライアントが実際に実行した結果ではありません。

## 会話の結果ページと必要時のファイル取得

小さなテキストは従来の形式で返します。会話への通常ツール結果が 16 KiB を超えると、全体を本機に保存して `harness_result_page` を返します。`get_tool_result_page(result_id, offset=next_offset)` で続きを読み、各ページの `text` を順番につないで JSON を解析します。`sha256` は全 JSON の UTF-8 バイトに対応します。この上限は本アプリの配信予算で、ChatGPT の添付判定の閾値ではありません。ページ取得は元のツールを再実行しません。書き込みの再試行前には指示本文を最後まで読みます。

画像・音声・リソースブロックは、最初に `$harness_file` 参照として返します。必要時だけ `get_tool_result_file(result_id, file_index)` で取得します。プロジェクト成果物は従来どおり `get_file_result` のバイトページで読み、ネイティブプレビューには明示的な `preview:true` が必要です。ファイルの取得時にはクライアントの承認が求められる場合があります。独自 UI を持つツールとネイティブリソースのプロトコルは、互換性のため従来の形式を維持します。

全スナップショットはアプリの MCP 設定ディレクトリ内の `result-pages/` に保存され、再接続・再起動後も取得でき、自動期限切れや自動削除はありません。ローカルファイルを削除すると参照が無効になります。元のツール・サービス設定・許可フォルダーに変更があると、データを削除せず読み取りを拒否します。クライアント専用 `_meta` はモデル用ページに含めません。保存に失敗した場合は完了済み操作の結果を隠さないよう元の結果を返し、本文を含まない診断を記録します。この場合はサイズ上限を保証できません。

## 完了時の状態

実在しアクセス可能なファイルを確認できます。会話にファイル名があるだけでは生成や添付の証拠になりません。

## うまくいかない場合

見つからない場合は完了状態、出力先、権限を確認します。返答の制限と破損は別です。分割して読むか本機で開いてください。すべてのクライアントにダウンロードボタンが出るとは限りません。
