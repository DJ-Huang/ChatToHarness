# バックグラウンドタスクを開始・確認・取消する

[English](../en/background-tasks.md) | [简体中文](../zh-CN/background-tasks.md) | [日本語](../ja/background-tasks.md)

> 現在のソースが対象です。この変更は未リリースです。

## 目的

時間のかかる作業を動かし、切断後も同じタスクを確認します。

## 始める前に

プロジェクト、コマンド、出力先を決め、重要なファイルを保存します。通常はクライアントから依頼します。

## 操作手順

1. 通常の非対話コマンドには復元可能な `start_task` を優先し、返されたタスク ID を残します。
2. 短いタスクは完了結果を直接返せます。実行中なら返された引数で同じタスクを照会します。
3. 終了したらログ末尾だけで判断せず、結果・終了状態・成果物を確認します。
4. 切断、アプリ再起動、クライアントのタイムアウト後は、元の ID で先に確認します。
5. 取消時はタスクを特定し、停止または完了を確認するまで状態を取得します。

### コピーして使える例文

例のパスは許可済みのプロジェクトの絶対パスに置き換えます。Windows では自分のドライブのパスを使ってください。

```text
/Users/demo/ExampleProject で指定したコマンドを永続バックグラウンドタスクとして実行し、ID を残してください。重複起動せず同じ ID を確認し、完了時は終了状態と成果物のパスを教えてください。
```

## 完了時の状態

進捗、上限付きの出力、最終状態を確認できます。プロジェクトのタスク一覧から探すこともできます。

## うまくいかない場合

ウィンドウを閉じる、接続を止める、アプリを終了するだけでは永続タスクが止まる保証はありません。不明な状態では成果物も確認します。自動で再実行されません。重要な結果はファイルにも保存してください。

### 既定の実行と待機上限（現在のソース）

通常の非対話コマンドには `start_task`、対話端末には `start_process` を優先します。`start_task.wait_ms` の既定値は 2,000 ミリ秒、`get_task_result.wait_ms` は 5,000 ミリ秒です。両方とも 0–10,000 を指定でき、0 は即時照会です。待機中に完了したタスクは状態・終了コード・上限付き出力を返し、実行中なら元のタスク ID と次の照会引数を返します。待機時間は実行期限や冪等識別情報に影響しません。切断や照会の取消では登録済みタスクを停止しません。端末起動と出力取得の待機は呼出しごとに最大 10 秒で、実際の待機上限を返します。

### ログと冪等キーの競合

`get_task_logs` は既定で先頭からページを返します。末尾の確認には `cursor` を省略して `tail:true` を指定し、全ページを読む必要はありません。返されたカーソルは変更せず使用し、ファイルサイズから位置を計算しないでください。不正なカーソルは `INVALID_CURSOR` と安全な照会引数を返し、保存ログの破損は `TASK_LOG_UNREADABLE` と報告します。

同じキーで再試行するときはコマンド、実行期限、成果物一覧を変更しません。`IDEMPOTENCY_CONFLICT` は今回の要求が拒否されたことを示します。返された引数で元のタスクを確認し、自動で別のキーに変更して保護を回避しないでください。修正したスクリプトは明示的な新しい操作です。非ゼロ終了は `TASK_EXIT_NONZERO` と実際の終了コードを記録し、接続障害とは区別します。
