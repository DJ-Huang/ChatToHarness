# タイムアウト・状態不明・返答なしに対処する

[English](../en/uncertain-results.md) | [简体中文](../zh-CN/uncertain-results.md) | [日本語](../ja/uncertain-results.md)

> v0.6.2 に対応しています。

## 目的

実際に何が実行されたかを調べてから再試行を判断します。

## 始める前に

時刻、依頼やタスクの ID、実ファイルやアプリの現在の状態を残します。

## 操作手順

1. 履歴で未開始、実行中、成功、失敗、不明を区別します。
2. 未開始なら、引数、規約、権限を整えてから再依頼します。
3. 開始後のタイムアウトや不明な状態では、ファイル、外部アプリ、関連タスクを調べます。
4. バックグラウンド処理は元のタスク ID を使います。安全な編集も元の記録を確認し、新しい同一編集を作りません。
5. 本機で成功し返答だけがない場合は、書き込みを繰り返さず結果を読み直します。
6. 再試行が必要なら元の処理と残すべき結果を明示します。

### コピーして使える例文

例のパスは許可済みのプロジェクトの絶対パスに置き換えます。Windows では自分のドライブのパスを使ってください。

```text
直前の操作の履歴と既存タスクを調べ、実際の状態と成果物を先に報告してください。書き込みやコマンドは再実行しないでください。
```

![タイムアウト・状態不明・返答なしに対処する](../images/help/ja/history-detail.png)

1 詳細、2 詳細コピー、3 詳細診断。 現在のリポジトリの画面と隔離サンプルによる操作例です。実際の接続やツール実行の成功を示していません。

## 完了時の状態

返答がないことと未実行を区別し、ファイルやコマンドの重複を減らせます。

## うまくいかない場合

本機の通信路への書き込みは受信の証明ではありません。再接続で再実行されません。取消も最終状態を確認し、依頼しただけで停止済みと扱わないでください。

### 保存された結果を復元する（現在のソース）

実行履歴の詳細に保存状態を表示します。「復旧情報をコピー」で元のタスクまたは結果の照会情報をチャットに渡せます。`get_execution_summary` も結果の参照を返します。通常のツールは小さい結果も大きい結果も保存できます。独立キャッシュの上限は 7 日・50 MiB で、容量不足では早期に期限切れになる場合があります。ネイティブプレビューの形式は維持し、復元用の読み取りでは新しいスナップショットを作りません。結果にはファイル本文などのユーザー内容が含まれる場合があり、ローカルの非公開フォルダーに保存されます。読み取り時にも現在の権限を確認します。保存失敗・期限切れ・保存結果のない旧記録は明示し、変更の再実行は行いません。

### ログのパスを推測せずに診断する

- ツールの失敗には、許可済みの `project_path`、`state:"errors"`、必要なら `since` を指定して `get_execution_summary` を呼びます。`include_connection:true` でアプリの接続イベントも取得できます。
- 切断・再接続・再試行の待ち時間には `get_harness_status` の `connection.events` を使います。アプリ全体の状態・時刻・再試行間隔だけを返し、他プロジェクトの呼び出し内容、生ログ、認証情報は含めません。履歴は有限で、空でも過去の切断がなかった証明にはなりません。
- タスクの標準出力・標準エラーには、元の `task_id` で `get_task_result` または `get_task_logs` を使います。

OS のログフォルダーやアプリの保存先を推測したり、診断のためにプロジェクト範囲を広げたりしないでください。範囲外のログ読み取りは拒否したまま診断ツールの引数を案内し、権限を広げたり代替呼び出しを自動実行したりしません。

トンネルの初回ポーリング待機は 1 秒です。予期しない終了を即時検出し、短い障害は素早く再試行、長い障害は 10／30 秒へ間隔を広げます。30 秒連続で接続できた後に間隔をリセットし、接続停止で予約済みの再試行を解除します。実際の復旧時間はネットワーク・サーバー・プロキシにも依存します。ツールの期限とタスクの再実行方針は変わりません。
