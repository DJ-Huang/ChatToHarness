# ChatToHarness 架构

[English](../en/ARCHITECTURE.md) | [简体中文](../zh-CN/ARCHITECTURE.md) | [日本語](../ja/ARCHITECTURE.md)

执行链路为支持的客户端 → OpenAI Secure MCP Tunnel → 本机 Tunnel runtime → 工程规范协议代理 → Desktop Commander。面向客户端只提供 Tunnel 接入；内部 stdio 和 loopback 健康端点不是新增的对外 MCP 服务。

## 桌面层

Electron 主进程管理配置、系统加密存储、单实例、窗口、后台图标和连接队列。HTML/CSS/JavaScript 提供四个真实页面；受限 preload 暴露设置、目录选择、状态订阅及连接操作。渲染器禁用 Node，启用沙箱、上下文隔离、导航限制和外部链接白名单。

窗口关闭只隐藏。停止与退出增加 actionEpoch，取消排队的自动连接及保存后的连接续步。窗口完成加载后才开始自动读取密钥，避免系统授权挡住初次呈现。状态只包含密钥是否保存，不返回明文或密文。

Mac 保留 LocalHarness 的内部名称、应用标识和状态目录，显示名称为 ChatToHarness；Windows 使用独立系统数据目录。系统加密不可用时拒绝明文回退，读取失败保留原设置。Windows 的用户级系统加密不表示同用户其他程序无法访问。

## 平台与受管进程

平台适配层提供组件位置、默认 Shell、用户环境、通道命令及进程监督。Mac 使用进程组和拥有进程清理；Windows 用编译的 Job Object 辅助进程约束受管子树，进程退出关闭 Job。Tunnel 密钥只通过环境传入，工具代理启动 Desktop Commander 前移除该变量。

平台组件由固定版本和校验值准备，自带 Node；工具配置与日志位于私有数据目录，保留用户真实 HOME／USERPROFILE，遥测关闭。Desktop Commander 配置目录适配只接受已知源码匹配，失配停止构建。

## 规范代理与搜索

`get_project_context(project_path, target_paths?, rule_paths?)` 保留项目、规范正文、索引和凭证，增加带 `blocks_writes` 的 `diagnostics`。项目范围决定规范作用范围，应用授权目录决定文件读取边界，两者分别检查；共享规则可跨项目读取，不能扩大目标或写入权限。AGENTS 缺失正常，引用失败软诊断，真正无法交付的适用 AGENTS 只阻断写入。

文件和搜索读取直接附带规范；有效凭证复用已交付正文。写入首次需要规范时返回正文与重试凭证，明确未执行。文件及目录元数据控制有界缓存，正文只有变化时重新读取和计算哈希，并合并并发加载；AGENTS 使用固定文件名检查，规则索引流式枚举并有明确上限。索引版本与已交付规范版本分开，无关索引变化不使写入失效。

`search_project` 直接使用已打包的 ripgrep，参数数组传递，不使用 Shell。默认字面量、2 秒、每页 100 条与前后 2 行；总匹配 1,000、保存 2 MiB、单页结果 64 KiB，最多并发 4 个，时间上限 10 秒。快照绑定项目与查询，闲置 5 分钟失效；完成、无匹配、超时、数量／体积上限和部分失败分别报告。原生流式搜索继续提供。

代理待处理请求有容量限制、60 秒默认截止和最多 180 秒的显式等待。取消传给上下文及搜索，断开会清理等待表、缓存与搜索进程。未转发的失败标为 `not_started`，已转发超时为 `unknown`，不自动重放操作；迟到结果丢弃。继续读取和清理操作绑定来源句柄，不依赖全局当前项目；已知清理不要求重读规范。工具 schema、输出 schema 与真实行为注解同步维护，移除不可用的网页组件提示。

## 应用更新

独立 `Updater` 从固定 GitHub 仓库读取已公开稳定 Release，验证版本、平台、安装包地址、大小与 SHA-256（支持 `SHA256SUMS.txt`）。只通过主进程的 Electron `net.fetch` 联网，以支持系统代理；渲染器仍禁用网络与 Node。更新 IPC 复用主窗口来源校验，外部地址由主进程已验证的 Release 决定。

默认启动后 10 秒和此后每 24 小时检查；开关保存在独立偏好文件，手动与自动检查合并并发，不访问密钥或连接队列。下载必须由用户启动，流式校验后再次验证安装包，先断开受管进程再打开安装包并退出。失败保留可重试状态，退出取消下载；旧的私有更新缓存 7 天后在后续检查时清理。测试模式不启动自动联网。

## 构建与交付

GitHub Actions 在原生 Windows x64、Mac arm64 构建，校验打包资源、运行隔离窗口和安装检查。只有双平台通过且上传文件核验成功后，才自动正式发布带更新说明与 SHA-256 的稳定版，并直接调用官网部署；公开 Release 不覆盖。Pages 独立构建，首页下载只使用已公开稳定 Release，源码和页面均不保存用户配置或凭据。

运行和验收边界见 [VERIFICATION.md](VERIFICATION.md)，维护流程见 [docs/RELEASING.md](RELEASING.md)。

## 语言支持

软件通过 `app/locales.js` 和 `app/i18n.js` 共享窗口与原生菜单的翻译，覆盖静态文字、无障碍标签、运行状态和已知错误。首次采用系统语言，用户选择单独存入 `preferences.json`，与加密配置分开。语言接口直接更新菜单和状态，不进入连接队列，也不修改 `actionEpoch`。路径、凭据和工具输出不做翻译。

官网在根路径（中文）、`/en/`、`/ja/` 输出完整静态页面，分别设置元信息、文档入口、下载状态和应用截图，并提供 canonical 与其他语言链接。切换入口在浏览器中记住选择；直接访问英文或日文地址时尊重指定语言。
