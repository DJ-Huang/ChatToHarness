# ChatToHarness 使用指南

[English](../en/GUIDE.md) | [简体中文](../zh-CN/GUIDE.md) | [日本語](../ja/GUIDE.md)

**将 AI 对话连接到本机执行环境。**

ChatToHarness 是一个桌面控制台，通过安全通道让支持的客户端使用本机文件、终端、Git 和开发工具，并在工具调用前自动交付适用的工程规范。

[文档目录](README.md) · [网站与下载](https://dj-huang.github.io/ChatToHarness/) · [版本与校验文件](https://github.com/DJ-Huang/ChatToHarness/releases) · [客户端接入](CLIENTS.md) · [架构](ARCHITECTURE.md) · [验证记录](VERIFICATION.md) · [发布维护](RELEASING.md)

## 安装与使用

支持 macOS 14+ Apple 芯片与 Windows 11 x64。安装包自带 Node、Tunnel runtime 和 Desktop Commander，无需另外安装开发环境。安装前查看对应 Release 中的签名状态；当前默认 Windows 未签名，Mac 临时签名且未公证，系统可能提示或阻止安装。

1. 从正式 Release 下载对应 `.dmg` 或 `-setup.exe`，安装并启动应用。
2. 在[服务控制台](https://platform.openai.com/settings/organization/tunnels)创建或选择 Tunnel，准备 Runtime API Key。相关组织／工作区需要具备使用权限。
3. 在“连接配置”填入 Tunnel ID 和 Runtime API Key；在“工作目录”选择文件工具可访问的目录。
4. 点击“保存并连接”。待本机工具检查通过、显示“通道就绪”后，按“接入与帮助”关联客户端。
5. 先让客户端执行只读操作，再在专用临时目录验证写入和读取。

应用界面支持中文、英文、日文；文档语言与界面语言独立。

不要把 API Key 发到聊天或提交到仓库。应用只保存系统加密后的密钥；界面仅显示“已保存”，保存后清空输入框。Runtime API Key 只交给 Tunnel，不交给工具进程。API 调用方需要独立的调用凭据。

应用关闭窗口后继续后台运行。左键点击系统后台图标打开窗口，右键使用连接、停止、日志和退出菜单。“停止连接”会停止通道和所有受管 MCP 服务，“退出 ChatToHarness”回收受管进程并退出。重复启动会恢复已有窗口。默认不随系统登录启动。

“通道就绪”只说明通道和本机工具可用，不说明某个客户端已经完成配置或实际调用。

在侧栏「界面语言」中可即时切换中文、英文、日文。首次使用跟随系统语言（其他语言回退英文），之后记住选择。原生菜单、后台图标菜单、状态、帮助和错误提示同步切换。独立的 `preferences.json` 保存语言与自动更新检查偏好，不读取或重写密钥，也不重连通道。官网顶部也可切换语言，并在浏览器中记住选择。

## MCP Servers

MCP 服务管理从 v0.5.0 起提供，可使用对应版本安装包或源码开发入口。

在 ChatToHarness 的 **MCP Servers** 页面配置服务。这些设置属于应用，由 Tunnel 客户端共享，不绑定某个 Agent。内置文件与终端工具保留原名称；Unity、浏览器等通过普通 MCP 服务接入，ChatToHarness 不内置其业务逻辑。第三方服务不要求设置工作目录，内置文件工具仍需要授权目录。

1. 添加稳定服务 ID、显示名称与传输类型。`stdio` 配置启动命令和参数列表，可选工作目录、环境变量与 Mac／Windows 覆盖。Streamable HTTP 配置 URL 和可选静态请求头；远程必须 HTTPS，HTTP 仅支持回环地址。不支持 OAuth 或旧式 HTTP+SSE。
2. 在应用的密钥字段保存认证值。密钥使用系统加密单独存储，服务配置与导出只保留引用，界面不会读取已保存的密钥。只配置服务所需的环境变量；服务按你的用户权限运行，不受文件工具目录白名单约束。
3. 连接前检查实际启动命令或 URL，确认信任；启动目标变化后需要重新确认。“连接测试”复用健康连接，不调用发现的工具。工具预览显示连接状态与实际协商的协议版本。
4. 将每个工具设为禁用、直接调用或每次本机确认。新工具默认禁用，定义变化后重新授权，服务声明的只读属性不能自动授权。本机确认只适用于展示的工具、参数与连接，并须在调用总截止内完成。
5. 启用并连接服务，按需在客户端刷新工具目录。第三方工具名为 `serverId__toolName`，例如 `unity__get_scene`；配置、信任和调用批准均在桌面应用完成。

JSON 导入支持本应用导出格式和常见的 `mcpServers` 配置。导入前先检查预览；导入服务默认禁用，导入不会执行命令。导出不包含密钥值、信任记录或工具授权。导入后在本机补齐缺失的密钥并授权工具，再连接使用。

单独禁用服务只停止该服务。“停止连接”停止 Tunnel 和所有受管服务，关闭窗口则继续后台运行。传输故障独立重连，不重放调用；已发出但丢失响应的操作，先检查目标应用状态再决定是否重试。认证、配置与协议错误需要修正。SDK `1.32.1` 不兼容仅要求 `2026-07-28` 协议的服务。

转发给第三方的工具调用默认总截止 60 秒、最高 90 秒（含本机确认）；序列化消息上限 8 MiB。应用自身的持久任务和内容读取另有独立的时限及配额。结果支持结构化内容与图片。已启用且受信任的 MCP 服务现在可为支持的客户端提供原生资源／资源模板与提示词，也有四个只读回退工具供仅支持工具的客户端使用。仍不支持资源订阅、completion、sampling 或 elicitation。普通应用诊断事件会过滤调用正文；但持久任务请求、有限任务输出和执行详情另行保存、分别受保留策略约束，可能含有用户数据。“通道就绪”不等于客户端已发现并调用新工具。

## Harness 工程工具与持久任务（v0.6.0）

用 `get_harness_status` 查询**实际运行**的版本、构建身份、设备、连接及分页工具目录；目录里显示“可用”并不证明客户端调用成功。选择应用已授权的工程目录后，`get_project_overview` 返回有界的文件、Git 摘要与 AGENTS／规则／Skill 索引。`git_status`、`git_diff`、`git_log` 是只读 Git 查询；`get_file_result` 按字节分页返回文件大小和 SHA-256，并支持有限的原生图片预览。所有工程级工具均须先由应用授权工作目录。

`get_project_context` 按外层到内层加载 AGENTS，规则支持 `globs`／`paths`、`tasks`／`task_keywords` 与 `alwaysApply`；规则只要适用的路径、关键词或始终生效条件命中即可加载。Skill 目录与 AGENTS 引用先返回索引，需要显式选择 `skill_paths` 才加载正文。规则与 Skill 共用 64 KiB 正文预算。上下文令牌只证明已交付，**不是权限凭证**，也不保证模型遵守。首次写入遇到新规范会先交付正文，明确尚未执行。

长时间命令使用 `start_task`，提供 `project_path`、命令和稳定的 `idempotency_key`，保留返回的 `task_id`。之后使用 `get_task_status`、`get_task_result`、`get_task_logs`、`list_tasks` 和 `cancel_task` 查看或取消。**提交成功不等于命令完成**。断线后先查询原任务；超时或 worker 心跳丢失时执行结果可能**未知**，不会自动重放。默认运行时限为 24 小时，最高 7 天，同时最多 4 个活跃任务，保留的任务身份上限为 1,024 条。持久 worker 是独立进程：**停止连接、退出或重启桌面 App 不一定终止正在运行的持久任务**，需要显式取消并查询最终状态。任务遵循 Desktop Commander 命令验证策略，但工作目录并非终端沙箱。

`apply_project_edit` 支持已授权 UTF-8 文本：新建用 `expected_sha256="absent"`，修改已有文件用当前 SHA-256，并提供稳定幂等键。一次调用完成写入、重新打开实际文件、完整哈希校验及最多 4 KiB 的 UTF-8 读回，返回撤销 ID 和 `verification`。`status="matched"` 且 `complete=true` 时可直接用返回正文核对，无须再读取一次；截断只影响预览，校验覆盖完整文件。同键重试仅重新核验，不重复写入；`undo_project_edit` 仅在当前文件仍匹配编辑后的哈希时恢复先前字节。出现后续改动冲突会拒绝覆盖，但校验与文件替换并非针对同时进行的外部写入的完全原子事务。PDF／DOCX／XLSX 等仍使用已有格式工具。项目级／工具级授权记忆可能因服务配置、工具定义或项目作用域变化失效。可选「允许所有工具」仅适用于**已启用且受信任**的下游 MCP 服务，不会绕过 ChatGPT 自身的确认。

## 执行记录与实时日志（v0.6.0）

侧栏「实时日志」下方有**默认折叠**的「执行记录」子菜单，再次点击一级入口可以展开或收起，日志页中的快捷入口也可直接进入执行记录。实时日志约每 2 秒增量刷新，支持全部／工具／连接／异常过滤、搜索、暂停／继续、自动跟随和重新载入。这是**有界的近期视图**，并非无损高吞吐审计流：两次轮询之间新增记录超过页大小时，中间部分可能被跳过。清空界面不会删除磁盘日志。

执行记录保留请求 ID、工具／服务、有限参数摘要、时间、执行状态、本机通道写入状态及关联任务 ID。**本机执行成功、本机写入成功、ChatGPT 最终收到结果互不等价**；没有客户端回执时远端确认仍为未知。可清理日志总预算 50 MiB，最长保留 7 天／最多 10,000 条执行记录，单任务输出上限 4 MiB；任务身份／防重放记录及其他应用数据不计入这 50 MiB。详细诊断需手动开启，最多占共享预算中的 10 MiB，30 分钟后自动关闭。脱敏属于尽力而为，不要在终端输出凭据。详见[执行记录规范](../execution-records.md)。

尚未执行的缺少范围参数和规范刷新分别显示为「待补全参数」「待读取项目规范」，可在全部／工具视图查看，不计入异常筛选。同一请求、相同执行状态和错误码的通道更新合并显示，原始日志仍保留各次事件。「响应已写入本机通道」只表示响应写入本机通信通道。

## 应用更新

在「接入与帮助」的「应用更新」中查看当前版本、检查更新和阅读版本说明；原生菜单及后台图标菜单也提供「检查更新」。发现新版本时，侧栏显示提醒。

默认启动 10 秒后检查正式发布版本，此后每 24 小时检查一次；可关闭「自动检查更新」。检查不需要通道或密钥，网络失败不影响工具与连接。自动检查只提醒，下载与安装由你点击触发。开关与语言一起保存在独立的 `preferences.json`，不修改凭据或重连通道。

点击「下载并安装」后，应用下载当前系统的安装包并核对大小与 SHA-256；校验通过后停止连接、打开安装包并退出。Mac 需将 DMG 中的新版拖入「应用程序」，Windows 使用安装向导。请先保存或撤销界面中未保存的配置，并结束正在运行的工具任务。开发模式仅检查版本。安装包缺失、下载或校验失败会显示具体提示，不启动安装。

## 工程规范自动加载

默认开启。向客户端说明任务和工程目录；文件、搜索及终端工具也可用 `project_path` 明确规范的适用根目录。

- AGENTS 与 rules 都可以不存在。读取、列目录和搜索直接执行，并附带规范或诊断；带有效 `project_context_tokens` 时复用已交付的正文，避免重复加载。
- 根目录到目标目录之间的 `AGENTS.md`／`agents.md` 按作用范围生效。首次写入若有尚未交付的规范，返回正文和重试凭证，明确操作尚未执行；客户端阅读后重试。完整规范响应包含 `retry_patch.project_context_tokens`：阅读返回的 `contexts` 后，将补丁合并到原参数并重试 `next_tool` 指定的原工具，无须再次调用 `get_project_context`；保留原有命令、内容及幂等键。规范不完整时仍提示先加载。终端、项目编辑和持久任务遵循同一恢复方式，服务端不会自动重放。没有规范的项目允许直接写入。
- 普通文档引用、缺失文件和 `{en,zh-CN,ja}` 等简写只形成诊断，不阻断操作。相对引用以所在 AGENTS 的目录解析；项目外共享规范可在已授权目录内读取，不扩大项目目标范围或写入权限。
- 适用 AGENTS 冲突、不可读或正文无法完整交付时，只阻断写入；读取与排查仍可继续。`get_project_context` 可显式加载项目、目标路径与所选 `rule_paths`，读取指定规则失败只影响这次请求。
- 规范正文单次合计最多 64 KiB，不静默截断。只对已交付规范的变化要求重新阅读；无关规则索引变化不会阻断写入。文件及目录元数据用于缓存失效，并检测新增、删除和嵌套规范。

文件与规则访问都以应用授权目录为边界，解析符号链接后再次检查。只能通过桌面应用调整授权目录，工具中的 `set_config_value` 不能修改 `allowedDirectories`。规范是项目资料，不能覆盖用户或平台指令；交付不代表模型已经正确理解或遵循。

## 搜索与失败恢复

普通代码检索优先用 `search_project`：指定 `project_path` 和 `pattern` 即可；默认字面量内容搜索，`regex` 启用正则、`ignore_case` 忽略大小写，`search_type="files"` 查文件名或 glob。`include_globs`、`exclude_globs` 可缩小范围，默认遵循忽略规则并跳过二进制文件。返回绝对路径、从 1 开始的行号和前后各 2 行上下文。`read_file` 的 `offset` 仍从 0 开始，读取第 N 行时使用 N−1。

默认每页 20 条、搜索预算 2 秒，可提高到最多 10 秒；单次最多保存 1,000 条匹配、2 MiB 结果，每页文字与结构化响应合计预算为 14 KiB，并为规范交付留出空间；搜索按业务条目使用原有游标，避免再套一层原始 JSON 分页。超时、数量或字节上限、部分文件不可读和没有匹配分别返回明确状态。超长行／片段有截断标记。`next_cursor` 读取已保存快照，不重新扫描；游标绑定项目和查询，闲置 5 分钟失效。新入口最多并发 4 个搜索。原来的流式搜索工具仍可使用。

网关调用默认总截止 60 秒、最高 90 秒，包含本机确认等待；内置代理较长的显式等待不能延长该总截止。尚未转发的超时返回 `execution_state="not_started"`，已转发的超时返回 `"unknown"`，不会伪装成没有执行，也不会自动重放写入、追加、移动或命令。读取／搜索可在确认状态后重试。已登记搜索与进程的停止操作不因规则变更受阻；重连后失效的句柄会明确报错。

目录设置**不构成终端沙箱**，Shell 仍按当前用户权限与真实环境执行。`start_process` 省略 `context_paths` 且提供有效的绝对 `project_path` 时，规范范围默认使用 `[project_path]`；显式提供的 `context_paths` 优先，普通系统诊断可用 `[]`。补全范围不改变命令工作目录或权限。长任务可在后台运行、分次读取输出；停止或退出应用会清理受管 MCP 进程，但独立的持久 start_task worker 可能继续执行，需要显式取消并确认终态。

## 开发时直接运行源码

Mac 双击仓库根目录的 `Dev.command`，Windows 双击 `Dev.cmd`。首次会准备固定版本的 Node、Electron 与工具组件，需要联网；以后读取当前 `app/` 源码，**不调用打包、不生成安装包**。已有依赖时也可以运行 `npm run dev` 或 `npm start`。

修改代码后，在应用菜单或托盘右键菜单选择“重启 ChatToHarness”即可加载当前源码，也可以再次双击同一个开发入口；这里不自动监听保存。旧实例先停止通道和工具进程、取消重连并释放单实例锁，新实例才加载当前源码。已有工作目录、密钥和界面偏好沿用原存储；新运行程序首次访问钥匙串可能需要系统授权。

Mac 开发启动会在 `.cache/dev-electron/` 生成并复用显示名称为 ChatToHarness 的原生应用壳，菜单栏因此显示产品名；仍直接加载仓库源码，不修改原始 Electron 依赖，不生成安装包。

开发启动窗口保持运行；使用 Ctrl+C 或关闭该窗口会结束本次开发运行。关闭应用窗口仍按原设计隐藏到后台，可以再次运行开发入口来替换它。重启会结束当前正在运行的工具任务。

首次从不支持开发重启协议的旧版本切换时，请从旧应用菜单选择一次“退出 ChatToHarness”；仅关闭窗口不能退出。若旧实例未退出，开发启动器等待最多 15 秒后明确报错，避免同时运行第二套服务。此后使用开发入口即可一键重启。更新固定依赖时若 Windows 提示组件正在使用，也先退出旧开发实例再运行入口。

## 从源码一键启动

Mac 双击 `Start.command`；Windows 双击 `Start.cmd`。首次准备锁定依赖并构建，以后复用已有应用。需要联网下载固定版本组件；正常应用启动不检查升级依赖。

开发与构建使用 Node 24.22.0：

```sh
npm ci
npm test
npm run build
npm run dist
```

`build` 生成当前平台未封装的应用，`dist` 生成 DMG 或 NSIS 安装包。必须在匹配的平台与架构构建；不能把 Mac 的依赖目录复制到 Windows。CI 在原生 Mac arm64、Windows x64 环境执行构建及安装检查。

## 配置与旧版兼容

原 LocalHarness 的 Mac 数据继续放在 `~/Library/Application Support/LocalHarness`，内部标识及钥匙串命名空间保留，避免改名导致密钥丢失。系统可能再次要求授权；读取失败时保留原文件，可在应用中重新填写。Windows 使用系统用户数据目录。测试使用临时目录覆盖，不访问个人配置。

应用设置、工具配置、日志位于私有数据目录。保留真实 HOME／USERPROFILE，Git、SSH 和开发工具继续使用原有用户配置。不要在客户端中添加本地 stdio 或本地 HTTP 入口；本产品的对外接入仅通过现有 Tunnel。

## 故障处理

| 现象 | 处理方式 |
| --- | --- |
| 工具组件检查失败 | 查看日志；源码入口重新准备组件，安装版重新安装匹配系统版本 |
| 密钥读取失败／等待系统授权 | 在系统窗口授权；仍失败时重新输入密钥，不删除旧配置文件 |
| 凭据或权限错误 | 核对 Runtime API Key、Tunnel 关联及 Read + Use 权限，修正后重连 |
| 网络异常 | 应用退避重连；可手动重连或停止，工具操作不会自动重放 |
| 客户端看不到通道 | 核对组织／工作区关联，保持应用运行并确认“通道就绪” |
| 工程上下文过期 | 客户端重新加载规范后再明确发起操作 |
| Windows 安装被系统阻止 | 检查下载来源、SHA-256 和 Release 签名说明；正式签名需要维护者证书 |

通过“查看日志”打开日志目录。支持材料请脱敏，不包含密钥、完整环境变量或个人工程内容。

## 直接查询与结果恢复

已知项目或路径时直接调用目标工具。连接异常时才查状态，需要了解结构时才查项目概览。普通检索优先使用 `search_project`（默认 20 条），文件按所需行范围读取，Git 使用专用只读工具。内置文件／文本工具直接返回数据，不再默认打开 Desktop Commander 的可选查看界面；明确请求的文件预览及第三方 MCP 交互界面仍保留。

`get_execution_summary` 按项目查询执行摘要，支持状态、工具及时间筛选，默认 10 条、最多 50 条，不返回命令、参数或完整输出。需要原始内容时才读取工具历史。`get_task_result` 同时返回任务状态、有界 stdout／stderr 尾部和日志游标，减少额外查询；不会重新启动命令。

较大的受支持内置结果返回 `harness_result_summary`，包含可用预览、完整结果编号及完整性标记。只有需要更多证据时才续读原始分页。标记 `requires_full_guidance` 的预览不代表指引已完整交付，重试写操作前仍须读完全部指引页。未知第三方结果保留原有格式。

通道就绪与工具健康分别判断。“部分工具不可用”表示即使安全通道正常，某个工具服务仍需处理。服务断开返回 `MCP_SERVICE_UNAVAILABLE`，与权限拒绝区分。诊断历史、日志写入和清理移至有界工作线程队列；诊断持久化尽力而为，任务身份和撤销记录仍保持原耐久写入。
