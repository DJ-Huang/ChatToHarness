# ChatToHarness 使用指南

[English](../en/GUIDE.md) | [简体中文](../zh-CN/GUIDE.md) | [日本語](../ja/GUIDE.md)

**将 AI 对话连接到本机执行环境。**

ChatToHarness 是一个桌面控制台，通过安全通道让支持的客户端使用本机文件、终端、Git 和开发工具，并在工具调用前自动交付适用的工程规范。

[文档目录](README.md) · [网站与下载](https://dj-huang.github.io/ChatToHarness/) · [版本与校验文件](https://github.com/DJ-Huang/ChatToHarness/releases) · [客户端接入](CLIENTS.md) · [架构](ARCHITECTURE.md) · [验证记录](VERIFICATION.md) · [发布维护](RELEASING.md)

## 安装与使用

支持 macOS 14+ Apple 芯片与 Windows 11 x64。安装包自带 Node、Tunnel runtime 和 Desktop Commander，无需另外安装开发环境。安装前查看对应 Release 中的签名状态；当前默认 Windows 未签名，Mac 临时签名且未公证，系统可能提示或阻止安装。

1. 从正式 Release 下载对应 `.dmg` 或 `-setup.exe`，安装并启动应用。
2. 在[服务控制台](https://platform.openai.com/settings/organization/tunnels)创建或选择 Tunnel，准备 Runtime API Key。相关组织／工作区需要具备使用权限。
3. 在“连接配置”填入 Tunnel ID 和 Runtime API Key；在“工作目录”选择文件工具可访问的目录。
4. 点击“保存并连接”。待本机工具检查通过、显示“通道就绪”后，按“接入与帮助”关联客户端。
5. 先让客户端执行只读操作，再在专用临时目录验证写入和读取。

当前应用界面为中文；文档语言与界面语言独立。

不要把 API Key 发到聊天或提交到仓库。应用只保存系统加密后的密钥；界面仅显示“已保存”，保存后清空输入框。Runtime API Key 只交给 Tunnel，不交给工具进程。API 调用方需要独立的调用凭据。

应用关闭窗口后继续后台运行。左键点击系统后台图标打开窗口，右键使用连接、停止、日志和退出菜单。“停止连接”只断开通道，“退出 ChatToHarness”回收受管进程并退出。重复启动会恢复已有窗口。默认不随系统登录启动。

“通道就绪”只说明通道和本机工具可用，不说明某个客户端已经完成配置或实际调用。

在侧栏「界面语言」中可即时切换中文、英文、日文。首次使用跟随系统语言（其他语言回退英文），之后记住选择。原生菜单、后台图标菜单、状态、帮助和错误提示同步切换。独立的 `preferences.json` 只保存语言，不读取或重写密钥，也不重连通道。官网顶部也可切换语言，并在浏览器中记住选择。

## 工程规范自动加载

默认开启。只需告诉客户端任务和工程目录，代理会在文件、搜索、写入和终端操作前要求获得工程上下文：

- 读取工程根目录到目标目录间的 `AGENTS.md`，兼容小写 `agents.md`，冲突时明确报错。
- 索引根目录 `rules/` 下 Markdown 的路径和标题；由客户端选择相关正文，也支持 AGENTS 引用的工程内规则文件。
- 每次调用携带上下文标识，规范更新、进入新作用范围或跨工程时重新加载；不同聊天不共享“当前工程”。

规则正文一次最多 64 KiB。越界引用、不可读、过大等情况不静默跳过。没有规则文件可以正常使用。自动交付由程序保证，理解和遵循规范由模型完成。不自动继承其他产品的专属规则目录。

文件目录设置**不构成终端沙箱**。终端以当前用户权限执行，保留真实用户环境。长时间构建、Unity 等任务应后台启动，分次读取结果；网络重连不会自动重放工具操作。

## 从源码一键启动

Mac 双击 `Start.command`；Windows 双击 `Start.cmd`。首次准备锁定依赖并构建，以后复用已有应用。需要联网下载固定版本组件；正常应用启动不检查升级依赖。

开发与构建使用 Node 24.22.0：

```sh
npm ci
npm test
npm run build
npm run dist
```

`build` 生成当前平台未封装的应用，`dist` 生成 DMG 或 NSIS 安装包。必须在匹配的平台与架构构建；不能把 Mac 的依赖目录复制到 Windows。CI 在原生 Mac arm64、Windows x64 环境执行构建及安装检查。

## 配置与旧版兼容

原 LocalHarness 的 Mac 数据继续放在 `~/Library/Application Support/LocalHarness`，内部标识及钥匙串命名空间保留，避免改名导致密钥丢失。系统可能再次要求授权；读取失败时保留原文件，可在应用中重新填写。Windows 使用系统用户数据目录。测试使用临时目录覆盖，不访问个人配置。

应用设置、工具配置、日志位于私有数据目录。保留真实 HOME／USERPROFILE，Git、SSH 和开发工具继续使用原有用户配置。不要在客户端中添加本地 stdio 或本地 HTTP 入口；本产品的对外接入仅通过现有 Tunnel。

## 故障处理

| 现象 | 处理方式 |
| --- | --- |
| 工具组件检查失败 | 查看日志；源码入口重新准备组件，安装版重新安装匹配系统版本 |
| 密钥读取失败／等待系统授权 | 在系统窗口授权；仍失败时重新输入密钥，不删除旧配置文件 |
| 凭据或权限错误 | 核对 Runtime API Key、Tunnel 关联及 Read + Use 权限，修正后重连 |
| 网络异常 | 应用退避重连；可手动重连或停止，工具操作不会自动重放 |
| 客户端看不到通道 | 核对组织／工作区关联，保持应用运行并确认“通道就绪” |
| 工程上下文过期 | 客户端重新加载规范后再明确发起操作 |
| Windows 安装被系统阻止 | 检查下载来源、SHA-256 和 Release 签名说明；正式签名需要维护者证书 |

通过“查看日志”打开日志目录。支持材料请脱敏，不包含密钥、完整环境变量或个人工程内容。
