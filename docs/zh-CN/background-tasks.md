# 启动、查看和取消后台任务

[English](../en/background-tasks.md) | [简体中文](../zh-CN/background-tasks.md) | [日本語](../ja/background-tasks.md)

> 适用于 v0.6.2。

## 使用目标

运行耗时工作，断线后继续查询同一任务。

## 开始前

明确项目、命令和输出位置；先保存重要文件。持久任务通常通过客户端发起。

## 操作步骤

1. 普通非交互命令优先使用可恢复任务 `start_task`，保留返回的任务 ID。
2. 短任务可以直接返回完成结果；仍在执行时，按返回参数查询同一任务。
3. 任务结束后检查结果、退出状态与产物，而不是只看最后一行日志。
4. 断线、重启应用或客户端等待超时后，先按原任务 ID 查询，避免重复启动。
5. 需要取消时明确指定任务；继续查询，直到确认终止或已经完成。

### 可复制的示例

请将示例路径替换为本机已授权的工程绝对路径；Windows 使用自己的盘符路径。

```text
在 /Users/demo/ExampleProject 启动我指定的命令作为持久后台任务，保留任务 ID。之后只查询同一任务，不要重复启动；完成后报告退出状态和产物路径。
```

## 完成后的表现

你可以查到任务进度、有限的输出和最终状态。项目任务列表可帮助找回任务。

## 没有成功时

关闭窗口、停止连接甚至退出应用，都不保证终止持久任务。状态未知时先检查任务和产物；系统不会自动重放。任务并发与保存输出有上限，重要产物请保存为文件。

### 默认执行与短等待（当前源码）

普通非交互命令优先使用 `start_task`，交互式终端使用 `start_process`。`start_task.wait_ms` 默认 2,000 毫秒，`get_task_result.wait_ms` 默认 5,000 毫秒，两者均接受 0–10,000；0 表示立即查询。短任务在等待内完成时直接返回状态、退出码与有限输出；仍在运行时返回原任务 ID 和下一步查询参数。等待时长不改变运行时限或幂等身份，断线或取消查询不会取消已登记的任务。终端启动与输出读取每次最多等待 10 秒，结果报告实际等待上限。

### 日志与幂等冲突

`get_task_logs` 默认从开头分页；查看末尾时使用 `tail:true` 并省略 `cursor`，不必遍历全部日志。游标只能原样使用返回值，不要按文件大小计算偏移。错误游标返回 `INVALID_CURSOR` 和安全的查询参数；已保存的日志损坏会明确报告 `TASK_LOG_UNREADABLE`。

同一幂等键重试时，命令、运行时限和产物列表必须保持不变。`IDEMPOTENCY_CONFLICT` 表示这次请求被拒绝，按返回参数查询原任务；不要自动换键绕过保护。修改后的脚本属于新的明确操作。非零退出会记录 `TASK_EXIT_NONZERO` 和实际退出码，不代表连接故障。
