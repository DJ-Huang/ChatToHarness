# 执行超时、状态未知或没有收到结果

[English](../en/uncertain-results.md) | [简体中文](../zh-CN/uncertain-results.md) | [日本語](../ja/uncertain-results.md)

> 对应当前源码；本次改动尚未发布。

## 使用目标

先确认真实执行状态，再决定是否需要重试。

## 开始前

记下操作时间、工具或任务 ID，保留实际文件或应用当前状态。

## 操作步骤

1. 先到执行记录搜索请求，确认是未开始、执行中、成功、失败还是状态未知。
2. “未开始”表示这次操作没有被执行；补齐参数、规范或授权后再发起。
3. “状态未知”或已经开始的超时：检查目标文件、外部应用和关联任务。
4. 后台任务使用原任务 ID 继续查询；文本安全编辑使用原操作记录核对，不另建同样的操作。
5. 本机执行成功但客户端没收到时，优先重新读取结果，避免再次执行写入。
6. 确认需要重试时，明确是哪次任务和希望保留的已有结果。

### 可复制的示例

请将示例路径替换为本机已授权的工程绝对路径；Windows 使用自己的盘符路径。

```text
检查我刚才那次操作的执行记录和已有任务，先报告实际状态和产物。不要重新执行写入或重复启动命令。
```

## 完成后的表现

你能把“没收到答复”与“没执行”区分开，减少重复文件和重复命令。

## 没有成功时

响应写入本机通道不能证明客户端已收到。应用不会在重连后重放操作。取消请求也需要确认最终状态；不能因为发送取消就宣布已经终止。

### 找回保存的结果（当前源码）

执行记录详情显示结果保存状态，可选择“复制恢复信息”，再在聊天中按其中的原任务或结果引用查询。`get_execution_summary` 也会返回结果引用。普通工具的小结果和大结果均可保存；缓存最多 7 天、独立上限 50 MiB，容量压力下可能提前过期。原生预览保持原格式，结果读取本身不再生成快照。结果可能包含文件正文等用户内容，保存在本机私有目录；读取仍检查当前来源权限。保存失败、过期或旧记录没有快照时会明确说明，不能据此重做写入。

### 直接查询诊断，避免猜日志路径

- 工具执行异常：调用 `get_execution_summary`，传入已授权的 `project_path`、`state:"errors"` 和需要的 `since`；加上 `include_connection:true` 可同时取得有界的应用连接事件。
- 断线、重连与重试等待：调用 `get_harness_status`，直接读取 `connection.events`。这些是应用全局的状态、时间和重试延迟，不含其他项目的调用内容、原始日志或凭据。返回的是有限历史，空列表不能证明之前没有断线。
- 任务标准输出与错误：使用原 `task_id` 调用 `get_task_result` 或 `get_task_logs`。

不要猜测 `~/Library/Logs`、AppData 或应用私有存储路径，也不要为查询诊断扩大项目范围。越界日志读取会保留拒绝状态并给出可直接调用的诊断工具；不会扩大权限或自动执行替代调用。

隧道首次轮询等待设为 1 秒；意外退出立即触发检测，短暂故障先快速重试，持续故障再退避到 10／30 秒。连续就绪 30 秒后重置退避，停止连接会取消待执行的重试。网络、服务端和代理仍会影响实际恢复时间；此设置不改变工具请求截止时间，也不重放任务。
