## 中文

### 更稳定、更少往返的 ChatGPT 网页工具体验

- **连接与工具健康分开显示**：工具服务故障明确显示部分能力不可用，保留脱敏启动原因，校验运行组件依赖。单个服务独立恢复，已转发的写操作不会自动重放。
- **常用查询直接返回可用结果**：减少不必要的状态和概览调用；搜索默认返回 20 条，Git、目录和搜索按业务条目分页。新增项目级 `get_execution_summary`，一次查询最近状态、耗时、错误原因和关联任务。
- **减少大结果和写入确认的往返**：已识别的大结果先返回有用的摘要，完整快照仍可按需读取。安全文本编辑在同次调用中重新打开文件，返回完整文件校验和及最多 4 KiB 的实际读回文本；幂等重试验证结果而不重复写入。
- **本地响应更轻**：诊断写盘和清理移到有界工作线程；后台任务结果一次返回状态、退出码、输出尾部及日志游标，执行历史同步实际 worker 状态。
- **三语帮助与入口**：新增由仓库文档生成的中英日帮助中心、页面级帮助链接，以及「接入与帮助」中的 GitHub Star 入口；修复 Windows 路径别名下执行摘要漏记录的问题。

### 验证与升级

- 本次网页验收中，文件查询、字符串搜索和异常摘要均在 Edge 的 ChatGPT 页面显示最终答案。
- 一组前后配对的小文本写入测试中，目标工具调用从 2 次降到 1 次，最终答案接收时间从 15.792 秒降到 9.448 秒（约缩短 40.2%）。这是单组样本，不代表平均性能或原版 v0.6.0 的对照基准。
- 更新后如客户端仍显示旧工具目录，请刷新或重新连接插件。原有配置保留；写操作超时后先检查原任务与文件，再决定是否重试。
- 超时配置没有放宽。首次调用前仍可能有网页／模型等待；不能保证消除超时。图片左侧约 60 秒为触发默认超时的场景估算，最高 90 秒为配置上限，额外开销未测量；右侧为一次成功实测，两者不能用来计算提速倍数。

## English

### More reliable ChatGPT web tools, with fewer round trips

- **Separate channel health from tool health**: report unavailable capabilities, retain redacted startup errors, and validate shipped runtime dependencies. Recover services independently without replaying forwarded writes.
- **Return usable answers directly**: remove unnecessary status/overview steps; default searches to 20 matches and paginate business items. Add project-scoped `get_execution_summary` for states, durations, errors and related task IDs in one request.
- **Reduce result and write-verification round trips**: return useful summaries for recognized large results while retaining complete snapshots. Safe text edits reopen the saved file and return its checksum plus up to 4 KiB of actual readback in the same call. Idempotent retries verify without rewriting.
- **Keep local responses responsive**: move diagnostic persistence and cleanup to a bounded worker. Task results combine state, exit code, output tails and log cursors; history follows actual worker execution.
- **Improve help and discovery**: add a repository-driven English/Chinese/Japanese help center, contextual help links and a GitHub Star entry in Help. Fix missing execution-summary records for authorized Windows path aliases.

### Validation and upgrade

- File lookup, string search and recent-error summaries displayed final answers in actual Edge ChatGPT acceptance runs.
- In one paired small-text write test, target calls fell from 2 to 1 and final-answer receipt fell from 15.792s to 9.448s (about 40.2%). This single pair is neither an average nor a clean original-v0.6.0 benchmark.
- Refresh or reconnect the plugin if the client retains an old tool catalog. Local settings are preserved. After a mutation timeout, inspect the original task and file before retrying.
- Timeout limits are unchanged. Web/model delay can remain before the first call; timeout elimination is not claimed. The image's ~60s is an estimated default-timeout scenario (up to 90s when configured), with unmeasured overhead; 9.45s is one measured success. These different paths do not establish a speedup ratio.

## 日本語

### ChatGPT Web ツールの安定性と往復回数を改善

- **接続とツールの状態を分離**：利用できない機能と機密情報を伏せた起動原因を表示し、配布コンポーネントの依存関係を検証します。サービスごとに復旧し、転送済みの書き込みを自動再実行しません。
- **通常の照会を直接完了**：不要な状態・概要取得を減らし、検索は既定 20 件、Git・ディレクトリ・検索は項目単位でページ分割します。`get_execution_summary` でプロジェクトの状態、時間、エラー、関連タスクを一度に取得できます。
- **結果取得と書き込み確認の往復を削減**：対応する大きな結果は概要を先に返し、完全なスナップショットも保持します。安全なテキスト編集は同じ呼び出し内でファイルを再度開き、チェックサムと最大 4 KiB の実読込テキストを返します。冪等リトライは書き直さず検証します。
- **ローカル応答の負荷を軽減**：診断の保存・整理を上限付き worker に移し、タスク結果は状態、終了コード、出力末尾、ログカーソルをまとめて返します。履歴も worker の実行状態に同期します。
- **三言語のヘルプを整備**：リポジトリの文書から生成する英中日ヘルプセンター、ページ別リンク、ヘルプ内の GitHub Star 入口を追加しました。Windows の許可済みパス別名で履歴が欠落する問題も修正しました。

### 検証と更新

- Edge の実際の ChatGPT 画面で、ファイル照会、文字列検索、最近のエラー概要の最終回答を確認しました。
- 小さなテキスト書き込みの一組の比較では、対象ツール呼び出しが 2 回から 1 回、最終回答の受信が 15.792 秒から 9.448 秒になりました（約 40.2% 短縮）。平均値やオリジナル v0.6.0 との同条件ベンチマークではありません。
- 古いツール一覧が残る場合はプラグインを更新・再接続してください。既存設定は維持します。書き込みのタイムアウト後は、元のタスクとファイルを確認してから再試行してください。
- タイムアウト設定は変更していません。最初の呼び出し前に Web／モデル側の待機が残る場合があります。図の約 60 秒は既定タイムアウトに達する場合の推定（設定時は最大 90 秒、追加時間は未測定）、9.45 秒は一度の成功実測です。両者から高速化倍率は算出できません。
