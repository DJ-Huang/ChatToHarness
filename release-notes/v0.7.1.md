# ChatToHarness 0.7.1

## 中文

### 主要更新

- **Computer Use 设备自动识别**：每个 Mac / Windows Harness 通过其 MCP 工具标题、描述和 `_meta["com.chattoharness/device"]` 上报持久设备 ID、主机名和平台。ChatGPT 会话可以通过连接的工具列表识别设备，用户无需记忆、输入或复制 UUID。
- **自动绑定设备身份**：调用所选 Harness 的 `computer_use` 时，服务器端自动绑定本机设备 ID，不再强制提供 `target_device_id`。如果提供了错误的 ID，则在任何原生输入前拒绝调用。
- **多设备操作约定**：只有一台可用时直接使用；多台设备但用户未指明时，先询问电脑名称；明确 Mac、Windows 或主机名时选对应工具。这个跨连接意图判断由 ChatGPT 客户端完成，Harness 不能独立知道所有其他连接，也不能强制 ChatGPT 弹出原生选择框。
- **跨屏鼠标操作**：整合此前的 `mouse_move`、`mouse_down`、`mouse_drag`、`mouse_up` 与拖动中断释放逻辑，Mac 工具协议和构建中已包含。

### 安装与验收

- 本地构建 **macOS arm64 DMG**，采用 ad-hoc 签名，未 Apple 公证；没有自动替换当前运行版本，也未推送或发布 GitHub Release。
- 更新后需重启应用，并刷新 ChatGPT 中对应的 Harness 连接才能获取最新工具注册。
- Mac 原生真实鼠标 GUI 验收中此前的 `CU_USER_INPUT_ACTIVE` 尚未完成整改/复验。**不要将单元测试通过等同于跨屏真实拖动已通过**。
- Windows 原生工具代码与协议已调整，本轮仅在 Mac 上验证，不代表 Windows 实机验收通过。

## English

- ChatGPT can read each connector's stable device ID, hostname and OS from MCP tool metadata; end users do not enter device UUIDs.
- The selected Computer Use connector automatically binds its own device ID; an explicitly wrong ID still fails before native input.
- If multiple connected devices are available and the user does not name one, the ChatGPT client should ask which device to use. This is a client routing convention, not a host-enforced modal.
- Mac arm64 package is ad-hoc signed and not notarized. Full native pointer-drag acceptance remains pending, as does Windows real-device verification.
